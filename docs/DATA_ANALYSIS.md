# 데이터·평가 분석 (2026-10-05)

## 1. 과제 요약

- 입력: 평가 샘플마다 초기 이미지 1장(640x480 PNG) + 행동 시퀀스 `(16, 6)` float32 (`data/eval/actions/sample_XXXXXX.npy`).
- 출력: 샘플마다 **정확히 16프레임** mp4 (`submission_kit/input_videos/sample_000000.mp4` … `sample_000215.mp4`, 216개).
- 점수: `0.3 × DINO + 0.3 × Video Feature(R3D) + 0.4 × Action MAE`, 낮을수록 좋다. Public = eval 의 사전 샘플링 30%, Private = 나머지 70%.
- 제약: 학습은 RTX PRO 6000(96GB) 1장 기준 4일 이내, 추론은 eval 전체 1시간 이내. 외부 데이터 금지, eval 데이터 학습 금지, API 모델 금지, 공개 가중치(상업/비상업 허용 라이선스)만 허용.
- 제출 CSV는 반드시 `submission_kit/make_submission_csv.py` 로 만들고 수정 금지.

## 2. 학습 데이터 (`open/data/train`)

LeRobot v2.1 포맷, SO-100 계열 단일 팔 로봇.

| 항목 | 값 |
|---|---|
| 데이터셋 / 업로더 | 128개 / 55명 (HF 업로더 이름이 폴더명) |
| 에피소드 / 프레임 | 11,132 / 1,025,666 |
| fps | 6 (원본 30fps 를 stride 5 로 다운샘플, 1개만 원본 50fps→10fps) |
| 16프레임 창 | 약 2.7초. stride 1 창 84.8만개, stride 4 창 20.8만개 |
| 해상도 | 640x480 123개, 1920x1080 3개, 1280x720 2개 |
| 코덱 | AV1 81개, H.264 47개 (OpenCV 4.13 으로 AV1 디코딩 확인) |
| 카메라 | 데이터셋당 비디오 키 1개 (`observation.images.image`) |
| 행동/상태 | 6차원: shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper (3개 데이터셋은 `left_*` 이름) |
| 에피소드 길이 | 중앙값 80프레임, 5%=42, 95%=165, 최대 1072. 17프레임 미만 35개(16프레임 창 불가) |
| 쏠림 | Chojins(체스) 13만 프레임으로 최대, 상위 10명이 전체의 55% |

- 작업은 대부분 pick-and-place(레고, 큐브, 과일, 인형), 체스말 이동, 큐브 재배치, 정리 등.
- parquet 컬럼: `action, observation.state, timestamp, frame_index, episode_index, index, task_index`.
- `action[t]` 는 `state[t+1]` 과 가장 가깝다 (MAE 합계: t+0 16.2, **t+1 11.2**, t+2 22.1). 즉 행동은 다음 프레임 목표 관절각이다.
- 행동 정규화 통계는 `data/train/so100_action_statistics.json` (mean `[3.0, 117.6, 109.8, 61.7, -29.4, 9.8]`, std `[26.4, 50.2, 46.6, 29.7, 62.5, 16.4]`). 채점기가 이 통계로 z-정규화한다.

## 3. 평가 데이터 (`open/data/eval`) — 가장 중요한 발견

- 216 샘플, 장면은 **두 종류**로 깨끗하게 나뉜다 (`scene.py`):
  - `sample_000000`–`000153` (154개): 회색 바닥을 위에서 내려다보는 카메라, 주황/흰색 SO-100 팔 2대, 빨강·파랑 큐브와 흰 상자.
  - `sample_000154`–`000215` (62개): 나무 책상, 검은 팔, 테이프·상자 등.
- **두 장면 모두 학습 데이터 128개 첫 프레임 어디에도 없다** (`grid.py` 로 전수 육안 대조, 썸네일 최근접 거리도 큼). 평가는 사실상 **보지 못한 환경에 대한 일반화** 문제다.
- 행동 분포도 학습과 다르다 (학습 통계 기준 z):
  - 장면0: wrist_roll z 평균 **+1.89** (학습 평균보다 118도 큼).
  - 장면1: shoulder_lift z **−2.61**, elbow_flex z **−2.18**. 관절 캘리브레이션 원점이 다른 로봇으로 보인다.
  - → 절대 관절각을 그대로 조건으로 넣으면 모델은 학습에서 본 적 없는 값을 받는다. **상대 행동(a_t − a_0) 또는 데이터셋별 정규화**가 필요하다.
- 연속 샘플끼리 이어지지 않는다 (|a0[i+1] − a15[i]| 중앙값 135, 샘플 내부 한 스텝 변화 중앙값 9). 샘플은 서로 독립된 클립이다.
- 16스텝 동안의 움직임: 한 샘플 안에서 |z_t − z_0| 평균 0.34. 거의 정지한 샘플은 6개뿐이다.

## 4. 채점기 (`open/submission_kit`) 동작

- 영상은 PyAV 로 모든 프레임을 디코딩, **16프레임이 아니면 오류**. fps·코덱은 무시. 해상도 검사 없음.
- 모든 프레임을 320x512 로 레터박스(640x480 → 427x320 + 좌우 검은 띠).
- **Video Feature**: torchvision `r3d_18`(Kinetics-400), 16x112x112 로 리사이즈한 512차원 특징의 코사인 거리.
- **DINO**: timm `vit_small_patch14_dinov2.lvd142m`, 프레임별 384차원 × 16프레임(0번 프레임 포함)의 코사인 거리.
- **Action**: 동봉된 `action_extractor.ckpt`(3D-ResNet + 양방향 GRU, 입력 16x320x512, 출력 16x6)가 영상에서 행동을 추정하고, eval `.npy` 행동과의 z-정규화 MAE 스칼라를 CSV 에 직접 기록한다. 6관절 동일 가중.
- 0번 프레임은 **주어진 초기 이미지 자체**여야 한다 (베이스라인과 행동 추출기 모두 frame 0 = 조건 이미지, action[0] 정렬).
- 참고 계산: 영상에서 추출된 행동이 a0 로 고정이라면 Action MAE ≈ 0.34, 학습 평균(z=0)이면 ≈ 0.93. 실제 정지 영상의 Action 값은 추출기 출력에 달려 있어 로컬 실행으로 확인해야 한다.

### 규칙상 주의 (Rule 7)

제출킷의 코드, 평가 모델, 체크포인트, **그리고 이를 통해 추출한 정보**는 학습·추론·**영상 선택**·보정·수정에 쓸 수 없다. 따라서:
- 제출킷 행동 추출기를 손실로 쓰거나, 그 점수로 eval 영상 후보를 고르면 위반이다.
- 학습 데이터 홀드아웃에서 체크포인트를 고를 때도 제출킷 점수 대신 **우리가 따로 만든 채점기**(같은 공개 모델 DINOv2·R3D + 우리가 학습 데이터로 훈련한 역동역학 모델)를 쓰는 것이 안전하다. 제출킷은 최종 mp4 가 확정된 뒤 CSV 생성에만 쓴다.

## 5. 베이스라인 (`open/baseline`)

- DynamiCrafter_512 의 VAE·OpenCLIP 이미지 인코더만 재사용하고, 11M 파라미터 소형 UNet 을 새로 학습(`baseline_diffusion.ckpt`, 87.6MB).
- 행동은 z-정규화 → MLP → 프레임별 timestep 임베딩에 concat. 첫 프레임 latent 를 고정 조건으로 사용.
- 320x512, DDIM 50 step, fp16. 공개 점수 0.517 로 첫 프레임 반복(0.303)보다 나쁘다.

## 6. 이 분석에서 나온 설계 결론

1. **배경 고정이 공짜 점수다.** 카메라가 고정이고 바뀌는 건 로봇 팔과 집은 물체뿐이다. 움직임 영역 밖은 초기 이미지 픽셀을 그대로 쓴다.
2. **처음 보는 환경**이라 소형 모델을 처음부터 학습하면 일반화가 안 된다(베이스라인 0.517). 대규모 사전학습 영상 모델이 필요하다.
3. **행동 조건은 상대값**으로 넣는다. 평가 로봇의 관절 원점이 학습과 다르다.
4. 학습/검증 분할은 **데이터셋(업로더) 단위**로 묶어야 평가 상황(새 환경)을 흉내 낸다. 체스 데이터 쏠림은 샘플링 가중치로 낮춘다.
5. 출력은 640x480 원본 크기, 16프레임, 0번 = 입력 이미지, 무손실에 가까운 CRF 로 저장한다.
