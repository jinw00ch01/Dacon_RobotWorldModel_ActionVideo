# 모델 아키텍처 계획 (목표: Public ≤ 0.15, 학습·추론 모두 RTX 5060 8GB)

근거: `docs/DATA_ANALYSIS.md`. 참고 점수(조사 기준): 공식 베이스라인 0.517, 첫 프레임 반복 0.303, Cosmos-Predict2.5-2B + LoRA 약 0.22, 대학원 트랙 2위 해법 0.175 (github.com/gxonu/Worldmodel-AI-Challenge), 최종 상위 3팀 약 0.14.

**2026-10-05 결정: 클라우드 GPU 는 빌리지 않는다. 모든 학습과 추론을 Galaxy Book6 Ultra (RTX 5060 Laptop 8GB, RAM 32GB, 여유 디스크 약 415GB) 한 대에서 한다.** 대회의 학습 4일·추론 1시간 제한은 RTX PRO 6000 기준이라, 노트북에서 돌아가는 파이프라인은 그 안에 들어간다.

## 0. 8GB 에서 성립시키는 원칙

1. **사전학습 영상 모델 + 작은 어댑터만 학습.** 평가 장면은 학습 데이터에 없다. 처음부터 학습한 소형 모델(베이스라인 0.517)은 첫 프레임 반복(0.303)보다 나쁘다.
2. **VAE·텍스트 인코더를 학습 루프에서 뺀다.** 학습 클립을 한 번 잠재(latent)로 인코딩해 디스크에 캐시하고, 텍스트 조건은 고정 문장 하나의 임베딩을 미리 계산한다. 학습 중 GPU 에는 확산 백본 + LoRA 만 올린다.
3. **메모리 절약 기본값:** bf16 가중치, gradient checkpointing, 배치 1 + gradient accumulation, 8-bit AdamW, 저해상도(예: 240x320) 위주 학습 후 짧은 고해상도 미세조정.
4. **긴 작업은 `wm_ops job start --kind gpu`** 로 앱 밖에서 돌리고 주기적으로 체크포인트를 저장해, 드라이버 리셋(TDR)이나 재부팅 뒤 이어서 학습한다.

## 1. 백본 후보 (설치된 diffusers 0.40 에 파이프라인이 있음)

| 후보 | 크기 | 라이선스 | 8GB 적합성 | 메모 |
|---|---|---|---|---|
| Cosmos-Predict2.5-2B (`Cosmos2_5_PredictBasePipeline`) | 2B DiT | NVIDIA Open Model | bf16 4GB + 활성값. 저해상도 LoRA 가능성 높음(추정) | 2위 해법의 출발점. diffusers 에 `CosmosActionCondition` 도 있어 로봇 행동 조건 변형부터 확인 |
| Wan2.1/2.2 1.3B 계열 (I2V/VACE) | 1.3B | Apache 2.0 | 여유 있음 | 첫 프레임 조건 지원, 가장 가벼움 |
| Stable Video Diffusion | 1.5B UNet | Stability Community | 저해상도 LoRA 가능 | 이미지→영상 전용, 로봇 월드모델 선행 연구가 많음 |
| LTX-Video 2B | 2B | 공개 가중치 라이선스 확인 필요 | 빠름 | 라이선스가 규칙 1 에 맞는지 먼저 확인 |

선정 기준: 홀드아웃 자체 점수, 8GB 에서의 학습 가능 해상도, 216개 추론 시간. 착수 전에 각 라이선스가 규칙 1(공개 가중치 + 허용 라이선스)에 맞는지 문서로 남긴다.

## 2. 구조

1. 백본 동결 + LoRA (attention·MLP).
2. **행동 인코더:** `(16,6)` → 상대 행동 `a_t − a_0` 와 차분 `a_t − a_{t−1}` 을 학습 통계로 스케일링 → 소형 MLP/1D-conv → 프레임별 임베딩을 timestep 임베딩에 더하거나 cross-attention 토큰으로 주입. 평가 로봇의 관절 원점이 학습과 달라(책상 장면 shoulder_lift z −2.6) 절대각은 보조 입력으로만.
3. **0번 프레임 고정:** latent 0번을 입력 이미지로 고정, 출력 mp4 의 0번 프레임은 입력 PNG 원본 픽셀.
4. **배경 앵커(후처리):** 생성 영상과 입력 이미지의 차이로 움직임 마스크(팽창·시간 누적·소프트 경계)를 만들고, 마스크 밖은 입력 이미지 픽셀로 교체. 임계값·팽창 크기는 홀드아웃에서 조정.
5. **역동역학 보조 손실:** 생성 latent 에서 행동을 회귀하는 소형 헤드를 학습 데이터로 함께 학습 (제출킷 추출기는 쓰지 않음, 규칙 7).
6. 학습 클립: 16프레임 @6fps. 데이터셋 균형 샘플링으로 체스(Chojins) 쏠림을 낮추고, 잠재 캐시는 데이터셋마다 일부 클립만 골라 크기를 조절한다 (전체 stride 4 창은 20.8만 개).
7. 증강: 색·밝기·화이트밸런스, 약한 crop/scale.
8. 마지막 체크포인트 여러 개 평균(EMA).

**추론:** 샘플당 1회 생성, 스텝 수와 해상도를 노트북 시간 예산에 맞춰 조정, 640x480 로 복원, 16프레임, 저CRF H.264.

## 3. 검증 체계

- **분할:** 데이터셋 단위 홀드아웃 10–12개 (검증 에이전트가 `configs/splits/` 에 고정).
- **자체 채점기 `wmscore`:** 공개 가중치 DINOv2-S/14 (프레임별 코사인 거리), torchvision R3D-18 (코사인 거리), 학습 데이터로 훈련한 역동역학 모델 (z-정규화 MAE). 제출킷과 같은 320x512 레터박스 전처리.
- **보정:** 홀드아웃에서 첫 프레임 반복과 공식 베이스라인을 채점해 리더보드 0.303 / 0.517 과 순서·간격이 맞는지 확인.
- 제출 1회당 변경은 하나. 기록은 `docs/EXPERIMENTS.md`.

## 5. 위험

- **연산:** 8GB 노트북 학습은 클라우드보다 훨씬 느리다. 0.15 는 상위 3팀 수준이라 노트북만으로는 어려울 수 있다(추정). S3 결과를 보고 해상도·데이터 양·스텝 수를 조정한다.
- **발열·전원:** 장시간 학습은 전원 연결, 절전 해제가 필요하다. 체크포인트 재개로 중단에 대비한다.
- **라이선스:** 백본마다 규칙 1 부합 여부를 문서화.
- **규칙 7:** 제출킷 모델을 학습·선택에 쓰지 않는다.
- **재현성:** 설정 파일 + 시드로 재현 가능하게 (수상권이면 코드·가중치 제출).
