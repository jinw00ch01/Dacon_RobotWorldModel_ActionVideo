# 모델 아키텍처 계획 (목표: Public ≤ 0.15)

근거: `docs/DATA_ANALYSIS.md`. 참고 점수(조사 기준): 공식 베이스라인 0.517, 첫 프레임 반복 0.303, Cosmos-Predict2.5-2B + LoRA 약 0.22, 대학원 트랙 2위 해법 0.175 (github.com/gxonu/Worldmodel-AI-Challenge), 최종 상위 3팀 약 0.14.

## 0. 가장 큰 제약: 연산 자원

| 자원 | 가능한 일 |
|---|---|
| Galaxy Book6 Ultra (RTX 5060 Laptop **8GB**, RAM 32GB) | 2B 영상 모델 **추론**(CPU 오프로딩), 저해상도 LoRA **실현 가능성 시험**, 소형 모델 학습, 특징 추출·자체 채점 |
| Galaxy Book3 Pro 360 (Iris Xe, CUDA 없음, RAM 16GB) | 데이터 파이프라인, 분할·인덱스, CPU 채점 재계산, 영상 QA |
| 대회 기준 | RTX PRO 6000 96GB 1장으로 4일 학습 |

0.15 이하를 낸 방법들은 2B급 사전학습 영상 확산 모델을 수십 GB VRAM 에서 미세조정했다. **8GB 노트북만으로는 그 학습을 대회 기준 시간 안에 재현하기 어렵다.** 그래서 두 갈래로 간다.

- **트랙 A (본선)**: 클라우드 GPU(48–96GB, 시간제 대여)에서 2B 모델 LoRA 학습. 노트북은 준비·평가·추론 담당. 비용이 들어 사용자 결정이 필요하다.
- **트랙 B (로컬 한계 시험)**: 같은 모델을 8GB 에서 저해상도·짧은 학습으로 돌려 어디까지 가는지 먼저 측정한다. 트랙 A 결정 전에도 바로 시작할 수 있다.

## 1. 생성 모델

**백본 1순위: Cosmos-Predict2.5-2B (Video2World)**
- 이미지+영상 조건 미래 예측용으로 학습된 공개 모델, NVIDIA Open Model License(상업 이용 허용) → 규칙 1 충족 여부를 착수 전에 문서로 확인한다.
- 2위 해법과 같은 출발점이라 재현 기준선이 있다.

**대안 백본** (라이선스 확인 후 비교): Wan2.2-TI2V-5B (Apache 2.0, 이미지→영상), Wan2.1-1.3B 계열 (Apache 2.0, 작아서 8GB 시험용), LTX-Video (라이선스 조건 확인 필요).

**구조 (2위 해법 + 이번 분석 반영)**
1. 백본 동결 + LoRA r32 (attention·MLP).
2. **행동 인코더**: `(16,6)` → **상대 행동 `a_t − a_0`** 와 프레임 간 차분 `a_t − a_{t−1}` 을 학습 통계로 스케일링 → 소형 MLP/1D-conv → 프레임별 임베딩을 timestep 임베딩에 더하거나 cross-attention 토큰으로 주입. 절대각은 평가 로봇의 캘리브레이션이 달라서(장면1 shoulder_lift z −2.6) 보조 입력으로만 쓰거나 데이터셋별 정규화 후 사용.
3. **0번 프레임 고정**: latent 0번을 입력 이미지로 clamp, 출력 mp4 의 0번 프레임은 입력 PNG 원본 픽셀.
4. **배경 앵커(후처리)**: 생성 영상과 입력 이미지의 차이로 움직임 마스크를 만들고(팽창·시간 누적·소프트 경계), 마스크 밖은 입력 이미지 픽셀로 교체. 마스크 임계값·팽창 크기는 설정값으로 두고 홀드아웃에서 조정.
5. **역동역학 보조 손실**: 생성 latent/프레임에서 행동을 회귀하는 소형 헤드를 학습 데이터로 같이 학습해 행동 반영을 강제(제출킷 추출기는 쓰지 않음, Rule 7).
6. 학습 클립: 16프레임 @6fps, stride 4 로 약 20.8만 창. 체스(Chojins) 등 대형 데이터셋은 가중치를 낮추고 데이터셋 균형 샘플링.
7. 증강: 색·밝기·화이트밸런스, 약한 crop/scale (평가 장면이 학습에 없어 외관 일반화가 중요).
8. 마지막 체크포인트 여러 개 평균(EMA/SWA).

**추론**: 샘플당 1회 생성(eval 216개를 1시간 내, RTX PRO 6000 기준), 640x480 로 복원, 16프레임, 저CRF H.264. 후보 여러 개 생성 후 고르기를 한다면 고르는 기준은 우리 모델 내부 점수만 사용(제출킷 금지).

## 2. 검증 체계 (제출 전에 점수를 예측할 수 있어야 한다)

- **분할**: 데이터셋 단위 홀드아웃. 새 환경 일반화를 흉내 내도록 평가 장면과 비슷한 탑다운·책상 장면, 다른 로봇 색을 포함해 10–12개 데이터셋을 검증용으로 고정.
- **자체 채점기 `wmscore`**: 공개 가중치 DINOv2-S/14 (프레임별 코사인 거리), torchvision R3D-18 (코사인 거리), 우리가 학습 데이터로 훈련한 역동역학 모델 (z-정규화 MAE). 제출킷과 같은 320x512 레터박스 전처리.
- **보정**: 같은 홀드아웃에서 ① 첫 프레임 반복, ② 공식 베이스라인을 채점해 리더보드 0.303 / 0.517 과 순서·간격이 맞는지 확인.
- 제출 1회당 변경은 하나. 제출 기록(설정, 코드 해시, 자체 점수, 실측 추론 시간, 리더보드 점수)을 `docs/EXPERIMENTS.md` 에 남긴다.

## 3. 단계별 목표

| 단계 | 내용 | 목표 Public |
|---|---|---|
| S0 | 첫 프레임 반복 제출로 파이프라인·채점 보정 | ≈0.303 |
| S1 | 자체 채점기 + 홀드아웃, 베이스라인 재채점 | 제출 없이 순위 일치 확인 |
| S2 | Cosmos-2.5-2B 제로샷/저해상도 LoRA (트랙 B) + 배경 앵커 | ≤0.25 |
| S3 | 클라우드 LoRA 전체 학습 + 상대 행동 인코더 + 역동역학 손실 (트랙 A) | ≤0.18 |
| S4 | 마스크·체크포인트 평균·증강 조정, 백본 대안 비교 | ≤0.15 |

## 4. 위험

- 연산 부족: 트랙 A 없이 0.15 는 어렵다고 본다(추정).
- 라이선스: 백본마다 대회 규칙 1 부합 여부를 문서화.
- Rule 7: 제출킷 모델을 학습·선택에 쓰지 않는다. 자체 채점기는 공개 가중치로 독립 구현.
- 재현성: 수상권이면 소스·가중치 제출이 필요하므로 모든 학습을 설정 파일 + 시드로 재현 가능하게.
